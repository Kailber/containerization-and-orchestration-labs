# Правила релизов фронтенда Кебабернетеса

## Как устроен релиз

- Релиз каждый день утром. Тег по дате: `vГГГГ.ММ.ДД`, например `v2026.10.14`.
- В релиз попадают все PR, смерженные в `main` с прошлого тега.
- Release notes публикуются как GitHub Release. Черновик готовит автоматизация, дежурный проверяет и публикует.

## Что считается важным изменением

Такие изменения всегда попадают в раздел «Важные изменения», даже если в PR они выглядят мелкими:

- любые изменения оформления заказа и оплаты (`src/features/checkout/`);
- изменения промокодов и акций, которые влияют на сумму заказа;
- изменения контракта с API бэкенда (`src/api/`): новые обязательные поля, удалённые или переименованные запросы;
- удаление или заметное изменение привычного сценария: перенесённые кнопки, новые или пропавшие шаги;
- включение функции для всех пользователей сразу, без feature-флага;
- обновления зависимостей, закрывающие уязвимости.

## Метки PR

Авторы ставят метки `feature`, `bug`, `breaking`, `chore`, `deps`, но не всегда и не всегда точно. Метка — подсказка, а не истина: если метка противоречит описанию и изменённым файлам, верить содержимому изменения.

## Что дежурный проверяет перед публикацией

- Все пункты раздела «Требует проверки» разобраны, сам раздел удалён.
- В «Важных изменениях» нет пропущенных изменений оплаты и промокодов.
- Ссылки на PR открываются.

## Что требует согласования с менеджером продукта

- Изменения оплаты и промокодов.
- Изменения, которые все пользователи увидят сразу, без feature-флага.
